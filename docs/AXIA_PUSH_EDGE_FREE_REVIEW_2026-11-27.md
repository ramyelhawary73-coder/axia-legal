## الحالة الحالية المعتمدة — 27 نوفمبر 2026
هذا التحديث يحل محل أوصاف «لم ينفذ» والمقترحات التاريخية أدناه. اعتمد المالك تجهيز PR #59 على Preview فقط، مع منع الإرسال وبدء نافذة الثلاثين دقيقة.

- طُبّق SQL التجهيز: `axia_push_preview_edge_prepare_pr59`؛ خمس جداول Push خاصة مع FORCE RLS وحصر الحساب والمكتب المعتمدين. بيانات الهوية الفعلية في ورقة المالك الخاصة وجدول التحكم فقط.
- نجحت إزالة pg_net الجديد غير المستخدم في `axia_push_remove_unused_net_preparation` بعد كشف أن postgres لا يستطيع تقييد ACL لكائنات supabase_admin. لا CASCADE ولا تجاوز صلاحيات؛ المصدر يوقف التثبيت عند بقاء الوصول العام. pg_cron موجود بلا jobs. **لا تشغل tick القديم؛ pg_net غير موجود.**
- أُنشئ LOGIN محدود `axia_push_preview_worker` في `axia_push_preview_limited_runtime_login`، بعضوية dispatcher فقط، بلا superuser/BYPASSRLS/DDL أو قراءة مباشرة لجدول الأجهزة وauth.users. عضوية المشغّل الإدارية ليست عضوية العامل.
- وُلدت مفاتيح التشغيل وحُفظت في مواضعها المعتمدة: أسرار Edge، HMAC في Vault، ومتغيرات خادم Vercel لفرع Preview وحده. لا قيم أسرار في Git أو التقرير، ولا مفتاح VAPID خاص أو اتصال قاعدة في Vercel. كل بوابات Push وEdge وSQL مغلقة؛ مركز التحكم مغلق.
- Edge `axia-push-preview` v1 منشور. POST مستضاف بعد حفظ الأسرار أعاد `503 PUSH_DISABLED`. هذا يثبت إقلاع البوابة المغلقة فقط؛ اتصال قاعدة المُرسل/TLS والإرسال الحقيقي غير مثبتين. محاولة pooler المحلية توقفت عند DNS `EAI_AGAIN`، وليست اختبار TLS ناجحًا.
- المصدر الوظيفي `857cf6176372b82ac9d17250b218db6de88f5af4` نجح في CI `46001049044`؛ 8 اختبارات Deno منها 13 فحص SQL. أُعيد نشر نفس المصدر بعد إعداد المتغيرات: Preview `dpl_8u6Z5iZusa4RWT8GQQXTNAzBsnom` جاهز READY. تعديل السجل اللاحق لا يغيّر شفرة المُرسل.
- إعادة القراءة: صفر أجهزة، صفر outbox، صفر Cron jobs، بوابتا SQL false ووقت البداية/النهاية NULL. نافذة 30 دقيقة لم تبدأ، ولا قبول Android مغلق/شاشة مقفولة بعد. بيانات الأعمال/Auth وعضويات المكتب لم تتغير؛ main وProduction لم يتغيرا.

### بديل الجدولة المجاني للمراجعة فقط
اقتراح: Cloudflare Workers Free كمؤقت محدود مرة/دقيقة يستدعي عنوان Edge الثابت بتوقيع HMAC وجسم فارغ؛ يظل الإرسال وبياناته في Supabase الحالي. ليس موردًا منشأً أو اختيارًا معتمدًا بعد.

| البند | التصميم وحد الاعتماد |
| --- | --- |
| الموارد المقترحة | Worker واحد وCron واحد؛ بلا KV/D1/Queues/خطة مدفوعة أو ربط دفع |
| أسرار Cloudflare | HMAC فقط بعد موافقة منفصلة على وجهته الجديدة؛ لا DB/VAPID/اشتراكات أو بيانات قضايا |
| القيم | scope الحالي، ref الحالي، عنوان Edge الحالي الثابت؛ flag=0 وT0/approved_until غير مضبوطين قبل الجاهزية |
| SQL المطلوب عرضه أولًا | استبدال اعتماد edge_begin على حجز pg_net بحجز ذري تحت قفل صف التحكم؛ ≤200 قبول/شهر، مرة/دقيقة، تحقق النافذة والحصر ومنع الإعادة، وإنقاص الميزانية عند القبول قبل التنفيذ |
| عدم تغيير السلوك | تبقى صلاحيات dispatcher المحدودة وMFA/الجلسة ورضا الجهاز والفحص الحي والوجهة الثابتة كما هي؛ لا وصول للمؤقت إلى قاعدة البيانات |
| التفعيل والإغلاق | نشر مغلق أولًا؛ تحقق انتشار Cron قبل T0، ثم اعتماد تشغيل 30 دقيقة منفصل. يمنع Worker وSQL الطلبات بعد cutoff، وإغلاق الأعلام؛ حذف Cron وحده ليس إغلاقًا فوريًا |
| التحقق المطلوب | اختبارات HMAC/النافذة/الإعادة/الميزانية والتزامن، أداء CPU الفعلي على Free، ثم فحص اتصال Edge بقاعدة البيانات مع الإرسال مغلق قبل اختبار الهاتف |

الوثائق الرسمية الحالية: Workers Free حتى 100,000 طلب/يوم و5 Cron Triggers للحساب و10ms CPU لكل Cron. حدود حساب المالك المتاحة لم تُقرأ؛ يلزم التحقق منها أولًا. تغييرات Cron قد تتأخر حتى 15 دقيقة، لذلك لا نبدأ نافذة الاختبار أثناء انتظار الانتشار. لا ضمان استقبال دائم أو موعد دقيق على خطة مجانية أو عند قيود الهاتف. لم تُنشأ موارد Cloudflare أو تُنقل مفاتيح إليها، ولم يُطبق SQL بديل.
المراجع: https://developers.cloudflare.com/workers/platform/limits/ وhttps://developers.cloudflare.com/workers/configuration/cron-triggers/ .

**الخطوة التالية:** جهّز كود مؤقت Cloudflare Free وSQL الحجز الذري واختباراتهما على فرع PR #59، ثم اعرض الحزمة وموضع HMAC وحصة الحساب للمراجعة قبل إنشاء المورد أو تطبيق SQL أو نقل المفتاح. أبقِ الإرسال ومركز التحكم مغلقين، ولا تبدأ النافذة أو تدمج main أو تنشر Production.

## تغييرات المصدر
- مُرسل يعمل مرة واحدة لكل طلب، بحد أقصى مهمة واحدة في الدقيقة، بلا watch أو sleep أو pool دائم. اتصال pg محدود يغلق في finally، وTLS يتحقق من الشهادة. Session pooler IPv4 على 5432، دون إضافة IPv4 مدفوعة.
- تثبيت `pg@8.16.3` و`web-push@3.6.7` داخل مجلد الدالة مع npm lock. `deno.json` خاص بالدالة، وNode compatibility تختبر في Deno 2.9.6. أوامر npm ci ثم deno task test موثقة أدناه.
- نقل النقل/التشفير وإعداد المرسل إلى `_shared` مع إبقاء واجهة عامل Node القديمة عبر re-export. لا نسخ متباعدة من ضوابط التشفير أو DNS.
- طلب Cron ثابت إلى `/functions/v1/axia-push-preview`، جسمه `{}` فقط، مع وقت وتوقيع HMAC قصير الصلاحية. لا عنوان جهاز أو مستخدم أو ملف قضية في الطلب. **لا يستخدم مفتاح Supabase Admin/Service Role**.
- مفتاح HMAC المخصص في Vault وبيئة الدالة مستقبلًا؛ SQL يخرج توقيعًا لمدة 60 ثانية فقط. لا يوضع المفتاح نفسه في queue. منع إعادة نفس الدقيقة في SQL، وقفل PostgreSQL خاص بالمُرسل يمنع تداخل الاستدعاءات. لا transaction مفتوحة أثناء اتصال المزود.
- يظل التصريح الحي قبل الإرسال: الجلسة الحالية وMFA والعضوية وحالة المكتب والرضا، ثم إعادة تحقق بعد DNS وقبل HTTPS. Android Chrome FCM فقط؛ لا ادعاء دعم آيفون عبر هذا المُرسل بعد.
- جاهزية المرسل تصبح heartbeat خلال 120 ثانية بدل 30 ثانية لتناسب الدقيقة؛ لا تمدد مدد Auth أو الرضا. اختبار المستخدم بعد +90 ثانية يصبح مؤهلًا عند أول tick تالٍ، غالبًا بعد 90–150 ثانية؛ لا وعد بتوقيت ظهور الإشعار على الجهاز.
- واجهة SSR مقيدة بالفرع الجديد وPreview والـOrigin الدقيق؛ main وProduction مغلقان افتراضيًا.

## معنى العزل وحدوده
هذا **عزل منطقي داخل قاعدة AXIA الحالية**، وليس مشروعًا مستقلًا. يشارك CPU/القرص والحصة مع البيانات الحالية. جداول Push غير مكشوفة مباشرة، FORCE RLS، لا وصول مباشر للمستخدمين أو المُرسل، وموافقة جهاز لمدة ≤15 دقيقة/JWT الحالي. `test_user_id` و`test_organization_id` غير محددين حتى يختار المالك حسابه ومكتبه المعتمدين. لا نغيّر عضويته/دوره ولا ننشئ عميلًا/قضية ولا ننسخ Auth/MFA. مركز التحكم يبقى مغلقًا. جسر التفويض يقرأ حقول الجلسة/العضوية المطلوبة فقط، بلا كلمات مرور أو رموز أو مفاتيح MFA.

يجب مراجعة سياسة Auth الحالية غير السرية وملء attestation قبل أي تفعيل؛ لا نفترض سياسة جديدة. لا ننشر مفاتيح شخصية أو endpoint في التقرير أو logs. عزل قاعدة مستقل بالكامل يتطلب حصة مشروع مجانية متاحة أو اختبارًا محليًا؛ لا نحذف/نوقف مشروعًا قائمًا لإفساحها.

## التحقق والحدود
- typecheck وlint و209 اختبارات تطبيق و11 اختبار SDK/نقل Node والبناء نجحت محليًا.
- 8 اختبارات Deno ناجحة، أحدها يحوي 12 فحص PostgreSQL بمُشغّل ترحيل **ليس superuser** يماثل صلاحيات postgres المستضاف في هذه النقاط، بالإضافة إلى 26 فحص أمان/تزامن لحزمة SQL الأساسية. تشمل الاختبارات: حصر الحساب/المكتب، النافذة، ACL، المتطلبات المفقودة، غياب Vault، توقيع SQL↔Deno، منع التكرار، الميزانية/الشهر، إرسال بمُرسل محدود الدور، heartbeat، والتراجع مع ثبات مستخدمي وجلسات وعضويات fixture.
- HTTPS حقيقي إلى loopback بشهادة محلية: VAPID وجسم فارغ، DNS lookup مخصص، رفض شهادة غير موثوقة ورفض redirect. لا إرسال FCM حقيقي.
- pg_cron/pg_net في اختبار SQL يستخدمان واجهات محلية بديلة لالتقاط الطلب؛ **لم تختبر الإضافات على Supabase المستضاف**. نشر الدالة/تغليف Supabase Edge Runtime نفسه وقيوده 2s CPU/150s wall-clock لا يُعد مثبتًا بمجرد اختبار Deno محلي؛ يجب التحقق في نافذة تشغيل معتمدة.
- لا نتيجة قبول موبايل فعلية بعد. Android مُغلق إغلاقًا عاديًا والشاشة مقفولة والإنترنت يعمل هو الاختبار التالي بعد التفعيل المعتمد. Force stop وانقطاع الإنترنت وقيود OS ليست ضمان توصيل.
- وصول Android لا يساوي قبول iPhone؛ دعم APNs/موافقة PWA على آيفون يحتاج مرحلة مستقلة. التذكيرات القانونية المستمرة وتجديد الرضا والتنظيف الدوري لم تُنفّذ في إثبات الجهاز هذا.
- فحوصات CI/Preview تخص آخر commit بعد الرفع وتوثق منفصلة؛ نتائج المصدر المحلية ليست نتيجة نشر أو استقبال فعلي.

## أمر الخطوة التالية
«راجع ملفات SQL والعزل المنطقي والمفاتيح المعروضة لمسار Push المجاني، وتحقق من فحوصات آخر commit والـPreview. حدّد لي حساب ومكتب الاختبار ومدة النافذة المطلوبة، واعرض حزمة التطبيق والتفعيل النهائية لاعتمادي، دون تطبيق SQL أو حفظ مفاتيح أو تشغيل إرسال أو دمج main أو نشر Production.»
